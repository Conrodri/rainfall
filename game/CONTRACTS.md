# Contrats entre systèmes (vague 1 : prototype)

Chaque agent code contre ces interfaces, même si l'autre côté n'existe pas encore. Pas de dépendance directe entre dossiers d'agents hormis ces points.

## Plateforme (autoload `Platform`)
- `input_mode` (TOUCH, KBM, GAMEPAD, dernier périphérique utilisé) + signal `input_mode_changed` ; `is_mobile()`, `is_ios()`, `is_pc()`, `has_touch()`, `can_quit()` (faux sur iOS), `interact_prompt()` (« [E] » / « [A] »), `ads_available()`, `show_rewarded_ad()`, `purchase()` (stubs).
- Actions de visée manette : `aim_left/right/up/down`. Sur PC les sorts 2-4 visent le curseur ; à la manette le stick droit ; sur mobile ciblage automatique.
- Affichage : PC 1920×1080 `keep_height` redimensionnable, mobile en paysage forcé 1920×1080 `keep_height` (orientation capteur paysage). Aperçu mobile sur PC : lancer avec `-- --mobile`.
- **Zone sûre (UX vague 2)** : `safe_margins() -> {left, top, right, bottom}` (px logiques base 1080 ; minimum `SAFE_MIN_SIDE` 48 côtés, `SAFE_MIN_EDGE` 32 haut/bas) ; `safe_override: Dictionary` (encoche simulée, prioritaire ; {} = système), `set_safe_override(insets)`, `check_safe_area() -> bool` (vrai si une marge a bougé) ; signal `safe_area_changed` (sondage `SAFE_POLL_S` 0,5 s sur mobile ou si `safe_override` posé, plus redimensionnement / reprise). Argument utilisateur `--safe=L,T,R,B` (ex. `-- --mobile --safe=132,0,0,0`), lu au `_ready`. `FloatingJoystick.apply_safe_area(safe)` : `offset_left = left + EDGE_GAP` (24), `offset_bottom = -bottom` (appelé par le HUD).
- **Retour Android** : signal `back_requested` ; `handle_back()` l'émet puis injecte Échap (pressé / relâché) sans changer le mode d'entrée : en partie = pause, dans les menus = Retour (`ui_cancel`). Jamais de sortie (`quit_on_go_back = false`).
- **Zones de frappe tactiles** : `SpellButton.HIT_PAD` (16 px, réduit sous 150 px de côté, 0 si non interactif), `hit_pad()`, `hit_radius()` = côté / 2 + `hit_pad()` (disque centré) ; `PauseButton.HIT_PX` (140, visuel `VISUAL_PX` 110), `hit_pad()` ; `InteractButton.HIT_PAD` (16, rectangle).
- `action_prompt_parts(action) -> Array` de {kind: "mouse"|"key"|"pad", button, text, icon?, caption?} (délègue à `InputLabels.prompt_parts` ; `icon`/`caption` seulement pour `pad` ; vide en tactile) ; `controls_help()` = `InputLabels.controls_help(input_mode)`.

## Entrées
- Le déplacement se lit avec `Input.get_vector("move_left","move_right","move_up","move_down")`.
- Le joystick tactile et les boutons de sorts **simulent les actions** (`Input.action_press(action, strength)` / `action_release`). Aucun lien direct UI -> joueur.
- Actions (`InputSetup`) : `move_*`, `aim_*`, `spell_2..4`, `dodge`, `interact`, `pause`. **Roulade `dodge`** : Shift gauche (`KEY_LOCATION_LEFT`) et Espace au clavier, LB à la manette (B et LT sont au sort 3), bouton tactile « Roulade » (`DodgeButton`) près des sorts. **Interagir = E seul** (Espace est passé à la roulade), A à la manette.
- **Remappage (`InputSetup`, UX vague 2)** : `REMAP_ACTIONS` = [action, libellé, groupe « jeu » | « coffre », pad remappable] (move_* clavier seul, spell_2..4, dodge, interact, chest_pick_1/2, chest_reroll_ad/gold) ; `SLOTS_KBM` 3, `SLOTS_PAD` 2 ; Échap, P, Start réservés. `bindings(action, device) -> Array` (copies), `default_bindings(...)`, `rebind(action, device, slot, ev) -> StringName` (conflit dans le même groupe : échange, renvoie l'action dépossédée, sinon &"") ; `clear_slot(action, device, slot) -> bool` (garde au moins une liaison) ; `reset(action := &"", device := "")` ; `load_overrides()` ; `is_default(action, device := "")` ; statiques `is_bindable(ev, device)`, `serialize_event(ev)` (« k:<code>[:<location>] », « m:<b> », « jb:<b> », « ja:<axe>:<+|-> »), `deserialize_event(s)`, `normalized(ev)`, `device_of(ev)`. Signaux `bindings_changed`, `pad_disconnected(device)`. Surcharges : settings.cfg section `[input]`, clé `<action>.<kbm|pad>` = tableau sérialisé (effacée si égale au défaut ; rien d'écrit en headless sur le vrai fichier). `last_pad_device` (-1), `pad_family_override` (« xbox »|« ps »|« nintendo »|« generic »). `apply_stick_deadzone()` : `GameSettings.stick_deadzone()` sur move_* et aim_*, relue toutes les `DEADZONE_POLL_S` (1 s).
- **InputLabels** (`scripts/ui/input_labels.gd`, sans class_name : `const InputLabels := preload(...)`, statiques) : `pad_family()` (override > dernière manette > 1re branchée ; xbox sans manette), `family_of_name(joy_name)`, `event_label(ev)`, `pad_label(ev, fam := "")`, `pad_icon(ev, fam := "")` (pad_a..y Xbox, pad_btn_bottom/right/left/top sinon, pad_lb/rb/lt/rt), `pad_caption(ev, fam := "")` (≤ 2 caractères, vide sur icône positionnelle), `prompt_parts(action, pad)`, `action_label`, `all_labels`, `movement_text()`, `controls_help(mode)` (0 tactile, 1 clavier-souris, 2 manette ; lignes [action, touches] d'après les liaisons courantes).

## Joueur (`scenes/player/player.tscn`, racine `CharacterBody2D`, groupe `player`)
- `func take_damage(amount: float, source: Node = null) -> void` (applique esquive, armure, réduction, bouclier ; plafond 25 % des PV max par coup de monstre, 40 % boss si `source.is_in_group("bosses")`)
- `func apply_status(status: StringName, data: Dictionary) -> void` : `&"burn"` {hit}, `&"slow"` {}, `&"poison"` {hit} (règles du joueur : Maths §4)
- `func heal(amount: float) -> void`
- `func apply_stats(stats: Dictionary) -> void` : bonus agrégés des items (clés ci-dessous, absentes = 0)
- propriétés lues par l'UI : `hp: float`, `max_hp: float`, `pickup_radius: float`, signal `hp_changed(hp, max_hp)`
- Cooldowns lisibles par l'UI : `func get_spell_cooldowns() -> Array` de {slot:int, remaining:float, total:float}
- Roulade : `func dodge(dir := Vector2.ZERO) -> bool` (dir nulle = `dodge_direction()` : déplacement, sinon curseur en clavier-souris, sinon `facing`), `is_dodging()`, `get_dodge_cooldown() -> {remaining, total, active}`. `Balance.DODGE_DISTANCE_U` en `DODGE_DURATION_S`, recharge `DODGE_COOLDOWN_S` (sans CDR). Pendant la roulade : `is_invulnerable()` vrai, `take_damage` et `apply_status` ignorés, `move_and_collide` (les murs bloquent, glissement le long), aucune collision monstre (masque 1).
- **Hitbox de dégâts unique** (22/10/2026) : `Player.set_hitbox_u(u)` règle le cercle de collision ET le rayon de dégâts (26 px × u / 0,5 ; 26 px sans `hitbox_u`). Lecture : `Player.hit_radius_px()` ou `PlayerHitbox.radius_px` (statique) ; boucle chaude des monstres : statique `Enemy.PLAYER_RADIUS_PX` (recopiée par `PlayerHitbox.set_radius`). Toute attaque (monstre, projectile, boss, mini-boss, piège) teste `rayon_attaque + rayon_joueur` via ces valeurs, jamais une constante locale. `Player.note_hit_from(pos)` : point d'impact d'un coup sans nœud source (projectiles), pour l'anneau. `HitboxRing` (`scripts/fx/hitbox_ring.gd`, groupe `hitbox_ring`) : anneau au sol + éclat directionnel au coup ; réglage `GameSettings.show_hitbox()` / `set_show_hitbox(tree, on)` (Accessibilité, actif par défaut).

### Clés de stats d'items (Dictionary passé à `apply_stats`)
`damage_add` (somme additive, 0.10 = +10 %), `damage_mult` (produit), `auto_damage_add`, `cd_damage_add`, `zone_damage_add` (sorts `is_zone` hors attaque auto : l'auto ne prend que `auto_damage_add`, 23/10), `elite_boss_damage_add`,
`attack_speed`, `cooldown_mult` (produit, 1 = neutre), `crit_chance`, `crit_mult_add` (ajouté au ×2), `max_hp_pct`, `max_hp_flat`, `armor`, `damage_taken_reduction` (déjà combinée hyperbolique),
`dot_taken_reduction`, `dodge` (blocage, combiné hyperbolique), `regen_flat` (PV/s × (1 + 0,2 (niveau - 1))), `burn_damage_add`, `move_speed`, `projectile_speed`, `range_add`, `zone_size_add`, `pierce`, `pickup_radius_mult`,
`xp_mult`, `gold_mult`, `luck`, `low_hp_damage_add`, `moving_damage_add`, `slowed_target_damage_add`,
`procs`: Array de {status:&"burn"|&"slow"|&"poison"|&"lightning", chance:float, data:Dictionary}, `specials`: Dictionary id -> stacks pour les effets uniques (Couronne d'écho, Phénix…).

## Ennemis (`scripts/enemies/`, groupe `enemies`, couche 3)
- `func take_damage(amount: float, is_crit: bool = false, element: StringName = &"", hit: Dictionary = {}) -> void`
  - `hit` (optionnel, appels à 3 arguments inchangés) : `source_pos: Vector2` (origine du coup, recul à l'opposé), `force: float` (force relative [0, 1] imposée, sinon `Balance.hit_force(dégâts, dégât de base, crit)`), `is_dot: bool`, `anim: bool` (éclat d'impact animé).
  - **Coup direct** (défaut) : flash blanc (`Balance.hit_flash_time`, coupé si `Quality.flashes_level == 0`), hitstop du seul monstre (`Balance.hitstop_time`, 16-80 ms, pas sur les boss, réarmement 0,1 s), recul si `source_pos` (`Balance.knockback_px × knockback_mass`, bloqué par les murs via NavField), étincelles `HitFx.impact`.
  - **DoT** (`is_dot`, ou élément `&"burn"`/`&"poison"`) : ni flash, ni hitstop, ni recul ; une particule discrète `HitFx.dot`.
  - Sources : projectile (`source_pos` + `anim`), nova (`source_pos` = centre), zone persistante (Cendres : `is_dot`), foudre en chaîne (`source_pos` = victime d'origine), statuts brûlure/poison (DoT). `SpellCaster.deal_damage(enemy, spell, hit := {})` relaie `hit`.
- Particules d'impact : `scripts/fx/hit_fx.gd` (`HitFx`), un seul nœud sous le Director créé avec le pool, pool fixe de Sprite2D, plafond 24 impacts/image (dont 10 DoT).
- `func apply_status(status: StringName, data: Dictionary) -> void` (règles côté monstres : Maths §14) : `&"burn"` / `&"poison"` {total, duration} = un cumul indépendant (dégâts totaux sur la durée), `&"slow"` {pct, duration}
- propriétés : `tier: int`, `is_elite: bool`, `hp`, `max_hp`, `is_slowed() -> bool`, `is_burning() -> bool`, `is_poisoned() -> bool`
- À la mort : `Events.enemy_killed.emit(self, global_position, tier, is_elite)` puis retour au pool. L'or et l'XP sont **déposés par le système de pickups** à l'écoute de ce signal (montants via `Balance.monster_gold/monster_xp` × multiplicateurs élite).
- Boss : groupe `bosses` en plus.

- **Cycle d'attaque armement / coup / récupération** (22/10/2026, `docs/Comportements_Monstres.md`) : tireurs, salves, bondisseurs et brutes sont immobiles pendant l'armement et la récupération (états SHOT, SALVO, RECOVER, constantes dans `Balance`). Jetons de tir : 3 tireurs au plus arment en même temps (`Enemy.charging_shooters()`, `Enemy.reset_shot_tokens()` pour les tests). `EnemyVisual.set_charge(level)` (lueur d'armement), `EnemyVisual.set_action(action, restart := false)`. `sprite_flash.gdshader` : un alpha de modulation > 1 donne une lueur chaude additive.

- **Rythme des boss et mini-boss** (22/10/2026) : chaque coup de corps passe par `BossPace` (`scripts/enemies/boss_pace.gd`, une instance `pace` par cerveau ; constantes `Balance.BOSS_PACE_*` par catégorie auto / sort / gros coup / charge / combo et par phase) : `wind()` → `strike(cat, phase, last)` → récupération immobile ≥ 0,3 s (`recovering()`, `planted()`), arrêt sur image et secousse à l'`impact()`. Un cerveau ne relance aucun coup tant que `recovering()` ; `owns_motion()` et `ignores_knockback()` vrais tant que `planted()`. Vérifié par `boss_pace_test` pour tout nouveau boss.

## Confort visuel et vibrations (22/10/2026)
- `GameSettings` est la seule source : `flash_scale()` (0 / 0,25 / 1), `shake_scale()`, `reduce_motion()`, `hitstop_enabled()`, `haptics()` / `haptics_strength()`. `Quality.flashes_level` n'est qu'un miroir.
- Tout nouveau flash passe par `LightRig.flash` (plafond 3 éclats forts/s) ou multiplie par `flash_scale()` ; toute secousse passe par `Main.shake` sans multiplier côté appelant ; tout arrêt sur image teste `hitstop_enabled()` ; tout tremblement/pulsation d'UI respecte `reduce_motion()`.
- Vibrations : `Haptics.pulse(Kind)`, `Haptics.hurt(amount, max_hp)`, `Haptics.connect_events()` (une fois, `Player._ready`) ; plafond 80 ms et 6/s, rien en clavier-souris.

## Director (`scripts/director/director.gd`, nœud `Director` dans la scène de jeu, groupe `director`)
- Spawn autonome selon `Balance` et `RunState.difficulty()`, plafond 250.
- **Vagues** (`waves_enabled`, constantes `Balance.WAVE_*`) : `WAVE_STREAM_SHARE` des crédits en flux continu (`credits`), le reste dans `wave_credits` ; toutes les `WAVE_INTERVAL_MIN_S`..`MAX_S` (RNG du Director) une vague de `WAVE_MIN_COUNT`..`WAVE_MAX_COUNT` monstres apparaît d'un même bord hors écran (même tier/variante à `WAVE_SAME_TYPE_CHANCE`, élite en tête selon `Balance.wave_leader_chance(D)`), dans la limite du plafond de vivants ; le reliquat repasse au flux. Annonce : son `telegraph.warn_heavy.heavy` grave + `WaveIndicator` (flèche au bord d'écran, `WAVE_ANNOUNCE_S`) sous `AmbianceManager.telegraph_layer`. Signal `wave_started(side: Vector2, count: int)` ; `trigger_wave() -> bool` ; lecture : `wave_timer`, `wave_count`, `last_wave_side`, `spawned_total`.
- `func spawn_boss(kind: StringName, position: Vector2) -> Node2D` (`&"mini"` ou `&"etage"`) ; émet `Events.boss_spawned`, puis `Events.boss_killed` à sa mort.
- `func set_zone(id: int, center: Vector2, radius: float, active: bool) -> void` : crédits ×1,5 et apparitions dans la zone quand le joueur y est.

## Pickups (`scenes/pickups/`, groupe `pickups`, couche 6)
- **Ramassage automatique (joueur, 22/10/2026)** : l'or et l'XP des primes (monstres, boss, Rançon, capsules, `PickupManager.drop`) sont **crédités tout de suite, portée infinie** : `RunState.add_gold/add_xp` (× `gold_mult`/`xp_mult` au moment du dépôt) + `Events.pickup_collected`, puis les pièces/orbes ne sont plus qu'un **effet visuel** qui vole vers le joueur (aucune attente, aucun ramassage, rien au sol au changement d'étage). Or des primes en pièces ENTIÈRES : `PickupManager.drop_bounty(at, or)` crédite la partie entière, la fraction (`gold_carry` < 1) est reportée sur la prime suivante (le compteur %d du HUD monte à chaque pièce). `sweep()` rend `{gold: gold_carry, xp: 0}`. Plus d'item d'aimant (`aimant_de_poche`, `aimant_d_ame` retirés ; `player.pickup_radius` n'a plus d'effet sur l'or/XP).
- **Ressources de joueur** (pièces de l'Avare, couteaux de Rictus, bras/jambes de Tocsin, tout objet de kit) : **toujours `GroundPickup`** (`scripts/pickups/ground_pickup.gd`, groupe `ground_pickups`, `GroundPickup.PLAYER_RESOURCE`) = ramassage MANUEL au contact (`contact_u`), jamais aimanté ni auto-crédité. Ne jamais passer une ressource de kit par `PickupManager` (tout ce qui y entre est crédité d'office).
- **Repère au sol** (`scripts/fx/ground_marker.gd`) : halo + anneau sous les ressources à ramasser (pulsé) et les invocations (fixe). Posé d'office par `GroundPickup.spawn` et `Decoy._ready`. API : `GroundMarker.attach(host, rayon_u, pulse, watch)`, `GroundMarker.of(host)`, `GroundPickup.set_marker_radius_u(r)` ; masquer le placeholder d'un pickup via `GroundPickup.show_placeholder` (jamais `visible`, qui masque aussi le repère). `GroundMarker.shape_id() -> StringName` : `&"diamond_dashed"` si pulsé (ressource), sinon `&"hexagon"` (invocation) ; ne rend jamais `&""` malgré son commentaire.

Sprites : `assets/sprites/props/gold_capsule/` (spec : `art/briefs/capsules.md`).

## Étage (`scripts/stage/`, `scenes/stage/`)
- Carte de test, points d'apparition (Marker2D en groupes `chest_spawn`, `pillar_spawn`), placement aléatoire seedé (`RunState.rng`), 8 petits + 2 larges + légendaire 25 %.
- Capsules d'argent (`scenes/loot/gold_capsule.tscn`, `scripts/loot/gold_capsule.gd`, `class_name GoldCapsule`, `Area2D` couche 7, groupes `interactable` et `gold_capsules`) : gratuites, `func setup(stage: int)`, `open() -> bool` (une seule fois), `is_opened()`, `expected_gold()`. `StageManager` en pose `Balance.CAPSULES_PER_STAGE` (10) à chaque étage, tirées avec `RunState.rng` **après** coffres et piliers (la disposition des coffres ne change pas) sur les cases « . » de la grille `data/maps/<id>.json` (sans grille : points libres de collision), à >= 4 u des coffres, piliers, téléporteur (position future sous le gros pilier) et départ joueur, >= 6 u entre elles (assoupli à 4 puis 2 u si la carte est trop étroite). `StageManager.capsules` ; libérées avec la carte au changement d'étage ; `to_dict()["capsules"]` ne garde que les fermées (`from_dict` les restaure ; ancienne sauvegarde sans clé = tirage neuf).

## Interaction (mobile d'abord)
- Tout objet interactif (coffre, pilier, téléporteur, futurs autels…) est dans le groupe `interactable` et expose :
  `func can_interact() -> bool` (joueur à portée ET action possible, ex. assez d'or, pilier non verrouillé) et `func interact_label() -> String` (« Ouvrir — 240 or », « Activer le pilier », « Partir »).
- **Répartiteur unique (22/10/2026)** : seul le HUD (`_update_interact`) lit l'action `interact`. Il appelle `interact() -> bool` sur la seule cible affichée par l'invite (la plus proche ; à ±16 px, `interact_priority()` : coffre 3 > capsule 2 > pilier 1 > téléporteur 0). Les objets ne lisent plus aucune entrée ; ils exposent `interact()`, `interact_state() -> {visible, enabled, label, hold_s}` (`enabled = false` : invite grisée, raison dans `label` ; `hold_s > 0` : maintien avec anneau, 0,6 s pour le téléporteur, **uniquement** ainsi, jamais au contact) et `interact_priority() -> int`. `can_interact()` / `interact_label()` restent le repli des anciens objets.
- Le HUD affiche un **bouton Interagir contextuel** (grand, zone du pouce droit) pour la cible du répartiteur ; il maintient l'action tant que le doigt est posé. `StageManager.TELEPORTER_OFFSET = (0, 300)`.

## UI (`scripts/ui/`, `scenes/ui/`)
- HUD : PV, XP/niveau, or, temps actif, jauge de difficulté (`RunState.difficulty_changed`), boutons de sorts avec recharge, bouton pause (appui long 0,3 s), joystick flottant moitié basse.
- Menu pause : `get_tree().paused`, reprise avec compte à rebours 3 s. L'UI tourne en `process_mode = ALWAYS`.

## Kits de personnage : hooks génériques (socle commun, 22/10/2026)
Un kit (`scripts/spells/<id>_kit.gd`, enfant « Kit » du joueur) ne touche jamais les champs privés du joueur ni d'Enemy ; il passe par :
- **Ressource** : `resource_state() -> Dictionary` construit par `KitResource.make()` (id, label, ratio, text, pips, filled, color, mark, blocked, boost). Lue par le HUD (`ResourceGauge`, PC à gauche de la barre de sorts, tactile au-dessus de la grappe) et le simulateur (`KitResource.level`).
- **Charges d'un bouton** : `slot_charges(slot) -> Vector2i(disponibles, max)` (Tocsin) -> `get_spell_cooldowns()[i]["charges"]` -> pastilles des SpellButton.
- **Roulade** : longueur = `kit.dodge_distance_u()` (variable en jeu) sinon `CharacterData.dodge_distance_u` sinon Balance ; vitesse de Balance constante (plus courte = plus brève). Sens réel : `kit.dodge_motion_dir(dir)` (bond arrière de Rainette). `Player.dodge_distance_u()` / `dodge_duration_s()`.
- **Lumière du joueur** : `CharacterData.light_color` / `light_core_color` ; **étalonnage de l'ultime** : `CharacterData.ultimate_grade_color()` (accent éclairci, Ardent #FFD6B0).
- **Coups et statuts** : `kit.ignores_hit(source)` filtre `take_damage` ET `apply_status` (data `source` posé par `Enemy.apply_affixes_to`).
- **PV max** : `kit.max_hp_mult()` + `Player.refresh_max_hp()`. Repli visuel : `CharacterData.placeholder_scale`.
- **Sauvegarde de run** : `save_state() -> Dictionary` / `load_state(d)` -> `player.kit` dans la sauvegarde (clé absente = état neuf).
- **Changement d'étage** : `floor_gold_kept(or) -> float` (Avare garde 50 % de sa bourse, StageManager.next_stage).
- **Monstre tenu** : statut `imprisoned` d'Enemy (`apply_status(&"imprisoned", {duration, release_pct, release_s})`, `imprison()`, `hold_at(p)`, `release_imprison()`, `is_imprisoned()`) ; jamais les boss.
- **Portrait** : `CharacterCard.portrait_info({"id": id})` (ui/portraits/<id>.png puis characters/<id>/portrait.png) pour le HUD et les menus.
- **Défense propre** (équilibrage 22/10/2026) : `kit.damage_taken_mult(source) -> float` (0-1) multiplie la part gardée dans `Player.take_damage` (après armure et items, sous `MITIGATION_CAP`) : garde du Montreur (Rictus), coffre-bouclier (Avare), vase compacte (Bourbe).
- **Auto-cast** : `kit.auto_cast_ok(slot) -> bool` consulté par `SpellCaster` seulement dans la branche auto-cast (option d'accessibilité, simulateur) ; jamais en manuel (Tocsin garde un bras pour les bottes, Averse garde l'eau de la Crue).
- **Coup porté** : `kit.on_spell_hit(spell, enemy, amount)` appelé par `SpellCaster.deal_damage` après chaque coup (Averse : eau sur élite/boss).

## Variantes de sorts (23/10/2026, infrastructure générique)
Chaque emplacement (slot 1-4) peut remplacer son sort de base par une variante débloquée. Le contenu (quelles variantes, chiffres, règles) vient de `docs/Variantes_Sorts.md` ; **un agent par personnage n'a que deux choses à faire** : déclarer la variante dans `data/characters.json` et la coder dans le kit.
- **Données** (`data/characters.json`, sous le sort de base `spells[i]`, slot = i + 1) : `"variants": [{"id", "name", "desc", "unlock_text"?, "unlock_rule"?, "unlock_key"?}]`. `id` unique dans tout le jeu (clé de déblocage `spell:<id>`, icône `icons/spells/<id>.png` ou `<perso>_<id>.png`, sinon icône de base désaturée). `unlock_text` facultatif (sinon déduit de la règle) ; `todo_design` n'est jamais affiché.
- **Règles `unlock_rule`** (moteur `scripts/save/variant_unlocks.gd`, sans class_name, évalué par `Profile.add_run_result` à chaque fin de run) :
  `{"type": "win_with"[, "character": id|"any"][, "mode": "facile"|"moyen"|"difficile"]}` gagner une run avec le personnage (défaut : propriétaire), mode minimal ;
  `{"type": "counter", "key": "<clé>", "value": N}` compteur cumulé `Profile.stats[<clé>] >= N` ;
  `{"type": "boss_kill", "boss": "<boss_id>"|"any"[, "character"][, "mode"]}` boss d'étage tué pendant la run ;
  `{"type": "floor_reached", "floor": N[, "character"][, "mode"]}` étage `RunState.stage` atteint (victoire ou non).
  **Sans `unlock_rule`, la variante du sort auto (slot 1) = `win_with`** (gagner une run avec ce personnage) ; les autres restent verrouillées. Type inconnu : warning, jamais débloquée.
- **Compteurs** : pendant la run, `RunState.add_counter(key: String, n := 1.0)` (clé conseillée `<perso>.<quoi>`, ex. `ardent.eclat_kills`) ; versés en fin de run dans `Profile.stats[key]` (`Profile.add_stat(key, n)`, `Profile.stat(key) -> float`). Le profil garde toute clé numérique inconnue de `stats`.
- **Kit** (`scripts/spells/<id>_kit.gd`, Ardent : `ardent_kit.gd`) : `static func variant(slot: int, variant_id: StringName) -> SpellData` rend un **nouveau** SpellData (slot et id forcés par l'appelant si absents), ou `null` tant qu'elle n'est pas codée. Appliqué par `CharacterData.for_id(cid, loadout)` -> `apply_loadout` ; inconnue / non codée / kit sans `variant` = **sort de base + warning, jamais de plantage**. Côté nœud Kit, le choix se lit par `player.character.variant_of(slot) -> StringName` (&"" = base) ou l'id du SpellData du slot. Comportement propre : `Behavior.KIT` + `kit.cast_spell(s, aim)` comme les sorts de base. La fiche affiche les chiffres de la variante via `CharacterData.variant_spell(cid, slot, id, quiet)`.
- **Sélection** : fiche Nouvelle run (`CharacterSheet`, souris / tactile / manette, focus visible), colonne de variantes masquée tant qu'aucune n'est débloquée (note « N variantes de sorts à débloquer en jouant »). `CharacterSheet.resolve_loadout(profile, c) -> {slot: id}` (base, remplacé par le choix mémorisé s'il est encore débloqué), `CharacterSheet.variant_quest(profile, c, slot, v)` (quête + « Progression : a / b » pour un compteur). Mémoire par personnage : `Profile.loadout` {cid: {"<slot>": id}}, `Profile.get_loadout(cid) -> {int: StringName}`, `set_loadout(cid, spells)`.
- **Run** : config `{character, mode, spells: {slot: id}}` (NewRunScreen, TitleScreen quick start, App « Rejouer ») -> `RunState.loadout` {int: StringName} (posé par App avant main.gd, `RunState.normalize_loadout(d)`), sauvegardé dans `run.loadout` (absent = base) ; `RunState.counters`, `RunState.bosses_killed` [{id, floor_boss}] aussi sauvegardés. Résultat de fin de run (main.gd) : clés `stage`, `counters`, `bosses_killed` en plus.
- **Annonce** : `EndRunScreen.unlock_text(&"spell:<id>")` = « Nouvelle variante pour <Perso> : <Nom> ! » (jamais l'id brut).
- **Test (TEMPORAIRE, à retirer avant sortie)** : `RAINFALL_UNLOCK_ALL_VARIANTS=1` ou `-- --unlock-variants` -> `Profile.unlock_all_variants` : toutes les variantes passent pour débloquées, rien n'est écrit au profil. Tests : `tests/variants_test.tscn` (kit factice `tests/variants_fake_kit.gd` via `CharacterData.kit_paths`).

## Passifs, dégâts affichés, fiche en gros plan (23/10/2026)
- **Passif d'un kit** : `static func passive_info() -> Dictionary` dans `scripts/spells/<id>_kit.gd`, construit par `KitResource.passive(nom, icône, intro, remplit, vide, paliers, hud := true)` (aides `KitResource.fmt/pct`). LISTE (cartes triées par `CharacterCard.sorted_by_difficulty`, stable, difficulté absente en dernier), DETAIL (`open_sheet_for(i)`, `close_sheet()`, `is_sheet_open()`) ; Retour/Esc/B ferme la fiche d'abord. `CharacterSheet` : sans défilement (texte réduit par `_fit_text`), modèle à gauche, passif et 4 sorts à droite ; clic/appui/A sur un sort = `preview_spell(slot, option)` (anim d'action `action_anim(sf, slot)` + VFX, repli squash, signal `spell_previewed`). `CharacterSheet.scaling_text(sd, short)` = « Niv. 1 : X · +Y/niv. ».
